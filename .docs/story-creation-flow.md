# 从候选故事到文字分镜

> 提取候选 → 选择故事 → 准备原文、摘要及两类要求 → 用户编辑确认 → 制作分镜

这条流程把选题、改编准备和正式制作分开。先确定讲哪篇故事，再核对事实、提出改编方向与验收标准，最后由用户确认后开始编排。

**制作要求和验收要求在「准备故事」阶段生成。等待用户选择或确认时，不生成分镜或图片。** 已独立分篇的故事可以直接选择，跳过候选提取。

## 一、流程总览

| 阶段 | 要解决的问题 | 系统产出 | 用户操作 |
| --- | --- | --- | --- |
| 提取候选 | 哪些故事值得选？ | 候选故事、简短介绍及来源定位 | 查看候选，或继续查找 |
| 选择故事 | 这次制作哪一篇？ | 已选故事及其原文范围 | 选择一篇故事 |
| 准备原文、摘要及两类要求 | 原文讲了什么，适合怎么改编，完成后检查什么？ | 原文、核对后的摘要、制作要求、验收要求及初步幅数建议 | 等待准备完成，查看结果 |
| 用户编辑确认 | 是否按这套方案开始制作？ | 用户确认的制作设置 | 查看原文，编辑要求、画风和叙事详略，点击「开始制作」 |
| 制作分镜 | 如何把原文编排成可读、可画的故事？ | 提纲、逐幅配文与画面描述 | 查看进展，必要时暂停 |

## 二、各阶段做什么

### 1. 提取候选

系统按用户选择的书籍、章节范围或主题寻找故事，并保存候选结果。候选用于帮助选题，包含故事名称、简短介绍和可用的来源定位。

候选介绍回答「这篇是否值得读」，不承担完整摘要的职责。此时不为每篇候选生成制作要求和验收要求，也不提前制作分镜。

用户可以从已保存的候选中选择，也可以继续查找。离开、刷新或重启后，已保存的候选仍可查看。

### 2. 选择故事

用户选择本次要制作的故事。系统记录选中的候选及来源范围，随后进入准备阶段。

选择故事确定制作对象；正式制作仍需在准备完成后确认。用户可以在开始制作前重新选择另一篇故事。

### 3. 准备原文、摘要及两类要求

系统先取得并保存所选故事的原文，再依据原文及必要的完整章节上下文，核对故事范围、人物、行动、因果和结局。

准备阶段形成以下内容：

| 内容 | 作用 | 内容边界 |
| --- | --- | --- |
| 原文与出处 | 提供事实依据 | 不凭记忆、其他版本或选题主题补写关键情节 |
| 故事摘要 | 说明发生了什么 | 交代起因、关键行动和实际结果；原作开放结尾保留真实停点 |
| 制作要求 | 指导如何改编 | 写本篇具体的叙事重点、交锋与回应、应保留的对白，以及可压缩的过程 |
| 验收要求 | 规定完成后检查什么 | 自动建议 2–4 条，每条都能从配文、画面描述或结语中核实 |
| 初步幅数建议 | 估计叙事空间 | 只是估计，后续编排与审核可以调整 |

核对摘要、估算幅数和提出两类要求使用同一次准备调用；两类要求不另增加一次模型调用。画风推荐按已有流程处理。

两类要求必须从本篇原文出发。验收要求既要对应改编选择，也要独立回查原文，避免把错误的制作建议直接变成验收标准。

「忠于原文」「画面生动」等通用要求由系统提示词负责，不重复填入本篇字段。自动建议应明确到具体人物、行动、回应或结果，让用户能够判断是否采用。

### 4. 用户编辑确认

准备完成后，用户可以查看原文，分别修改或清空制作要求、验收要求，并选择画风与叙事详略。

编辑内容先保存为草稿。完成编辑、关闭面板或刷新页面，都不等于开始制作；只有点击「开始制作」，才应用确认的设置并进入正式生成。

两类要求可各写最多 1,200 字。验收要求每行一条，自动建议为 2–4 条，用户编辑后最多可保留 20 条。清空字段表示不添加这类自定义要求，系统通用规则仍然生效。

叙事详略表达展开程度：简短紧扣主线，适中保留完整因果与关键转折，详细展开必要动作、反应与停顿。三档不对应固定幅数。

### 5. 制作分镜

用户确认后，系统直接依据原文、制作要求、画风和叙事详略编排故事，形成提纲，再按需要细化为逐幅配文与画面描述。

摘要另行保存，供后续审核检查完整性，不作为分镜编排输入。验收要求也不作为分镜生成输入。

本阶段的产物是文字分镜。画面描述说明每幅应画什么，并不代表图片已经生成。

## 三、制作与验收如何分工

**制作要求指导创作，验收要求用于判断结果是否达标。** 两者相关，但职责不同。

以下以《庄周梦蝶》说明字段的写法，仅作示例，不是固定模板：

| 字段 | 示例 |
| --- | --- |
| 故事摘要 | 庄周梦中化为蝴蝶，醒来发现自己是庄周，由此对梦与醒、庄周与蝴蝶的关系产生疑问。 |
| 制作要求 | 重点呈现梦中化蝶的自在与醒来后的疑问，保留梦与醒的对照，不增添后续情节。 |
| 验收要求第 1 条 | 分镜交代庄周梦中化蝶及醒来的先后关系。 |
| 验收要求第 2 条 | 醒后的疑问保留原文的开放性，不添加确定答案。 |

全篇审核时，系统接收验收要求，逐条给出结论和依据；制作要求同时作为理解改编意图的背景，不自动把每项偏好升级为额外验收门槛。

| 验收结论 | 含义与后续处理 |
| --- | --- |
| 通过 | 有具体分镜或原文依据支持该条要求 |
| 未通过 | 能指出具体缺失或错误；可修项进入定向修订，再全篇复核 |
| 无法判断 | 要求冲突、缺少依据，或超出文字分镜可判断的范围；停止绘图并说明原因，等待用户调整 |

修订接收审核提出的具体问题和制作要求，不直接接收整份验收要求。修后仍须重新审核。文字稿稳定并通过审核后才绘图；文字验收通过不代表实际图片已经合格。

## 四、编辑、重启与重选

- **草稿保留：** 已保存的编辑在刷新、离开或重启后继续保留；准备期间保存的用户草稿优先于迟到的自动建议。
- **清空保留：** 用户明确清空的字段不会被自动建议重新填回。
- **重新准备同一篇：** 保留已编辑的要求，不重新生成一套要求覆盖用户选择。
- **重新选择另一篇：** 替换未改动的自动建议，保留用户自写或修改过的内容及明确清空的选择。保留的内容仍应由用户核对是否适合新故事。
- **制作后修改：** 修改制作要求会重新编排；仅修改验收要求会保留分镜与可复用图片，重新审核。审核若引发画面描述或结构变化，再核对图片复用范围。
