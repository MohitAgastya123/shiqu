## 设计

- 采用SQLite最小增量迁移保存命令回执与故障实例；任务保存失败、恢复领取及命令受理通过原子SQL/数据库触发器建立一致性，避免在仅提供异步prepare接口的数据库上跨await持有事务。先以隔离SQLite做有界探针；若触发器无法保持原子性或可恢复性，更新设计并重审，不继续堆补偿逻辑。
- 任务按实际生成输入建立身份，剔除displayTitle等非生成元信息；已有图片成果按有效输入复用，不因改名失效。
- 故障实例归属工作、输入与范围；命令绑定故障实例与稳定requestId。显式恢复只领取对应故障及必要图像发布任务；普通失败再次发生产生新实例并接替旧实例。队列成功、失败与中断更新回执，保留历史，重放命令只读结果。中断自动重试沿用原有3次上限。
- `ReaderProductionCoordinator`统一决定普通工作、恢复工作和本地收尾资格；SessionView增加精简故障/恢复元信息，不把大历史塞入轮询。会话完成必须无未解除故障；在途保存不得覆盖独立故障记录。
- 图片按明确POST检查当前保存地址和真实文件；前端onError只触发检查，不付费。确认失效建立持久故障、取消完整声明；恢复前再次检查，文件已恢复则复用。模型结果与发布分开恢复，首幅是真实依赖。
- 重选先建立不列入书架/计数/最近阅读的草稿，草稿仅有真实查看需求才查找；选择另一篇才原子提交到同一家族。草稿可以复用既有intake与候选生产，禁止制作确认/分镜。提交继承最新控制与模式、清新故事产物，历史不复用作新选题结果；取消丢弃草稿并只读刷新当前版。
- 普通修订与替换共享家族epoch/可编辑基版比较；旧版不能作为新首次提交基版。现有revision记录可作为版本提交持久回执；不重复引入版本系统。
- 前端为每个用户命令保留请求身份，传故障/输入身份；已知新故障才创建新授权。界面展示多故障与暂停、恢复准备及按幅动作，按钮与实际调用对齐。API对没有授权身份的旧付费重试请求拒绝；普通无副作用轮询/需求心跳保持原用途，测试fixture升级请求契约。
