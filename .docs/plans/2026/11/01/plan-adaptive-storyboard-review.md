# 按叙事需要编排与审核画幅

REQ: `.docs/reqs/2026/11/01/req-adaptive-storyboard-review.md`

Git base: `56b0b82a8aa558e5fd4ddccf74dc27b9ce7fb2b3`。开始时工作树干净；此前九篇实际重编、回执和媒体仅存忽略目录，不纳入源码提交。

风险 non-low：审核输出、持久化检查点、付费队列屏障与图片位置有协调变化。使用现有自动幅数标记、repair 步骤和事务锁，不新建调度系统或迁移历史成品。

## 设计决定

1. 保留 `Selection.length` 的数值历史/旧 API。新建 UI 提交 `auto`；制作草稿和修订支持该值，叙事详略/全篇要求触发重编时切 auto。旧故事仅改配文/余味/画风时保留原 length 和编排，不因默认字段切换而重编；详略编辑入口明确请求自动重编。推荐仍承担原文摘要核对，但数量仅供估计。自动故事不再等待单独的幅数确认；制作确认保留故事、画风、详略和要求的确认。
2. 审核增加有界 coverage 记录：原文短引、叙事任务、对应幅号、充分/需改的判断及理由。真实提供方输出契约要求记录，历史回执无记录仍可读。独立重建主线，不按旧提纲、摘要或任务清单自证。需改项必须有问题，原文短引需能在所给原文/章节找到（仅简繁、标点及空白归一）。
3. 自动模式下 `requiresReplan` 不再要求用户手定幅数，转入已有 repair 步骤的结构分支。新增 provider `restructure`：返回按原幅号排序的区间替换 edits（允许空区间插入、空 pages 删除），仅编辑有问题的连续范围；纯函数先校验再应用。保留元数据、人物与原文，完整计划为事实检查对象。已完成但过期的 outline 不再作为审核约束，修订历史保留区间编辑和前后幅数。
4. 结构修订后 review 回到 pending，计入同一修订上限，无变化立即停止。旧数值模式保留原有结构阻止行为。无需新任务种类/池，检查点与使用量通过现有 CAS 保存。结构编辑同时生成新幅→旧幅/null的来源映射，计算旧阅读位置→新位置的映射，随文稿在同一次锁定保存中调整数据库当时的阅读位置，删除项回落至有效位置；不得覆盖并发阅读进度或留下越界幅号。
5. 跨位置复用按精确 prompt 匹配，要求原有全局输入和首幅参考稳定。有结构编辑来源映射时严格按映射核对，每个旧索引最多用一次；普通局部修订有同位置来源映射。全篇重编没有可靠映射时，只匹配新旧均唯一的 prompt；完整 prompt 顺序完全没变的纯配文修订可按原位置复用重复项。不能以增删后的相同数组位置猜配重复项。初次编排/结语完成可对父版查找，后续修订只重映射当前已核定图片，避免父版查找覆盖明确来源。实际重绘提示以已核定图片为准。
6. UI 内部旧 tab id `count` 可保留以兼容编辑入口，用户可见内容改为叙事详略；修订影响对自动篇幅显示估计/待编排，不承诺最终幅数。旧的 count 确认组件改为自动继续，数值接口仅作兼容。
