# Story import and automatic series plan

## Goal

A local Word/PDF story becomes a complete, ordered comic series through one confirmed creation flow. Automatic source partitioning, independent coverage review and continuity reuse must preserve important story development while production remains restartable and uses the existing engine.

## Current Context

The clean `main` at `5624163` is now checked out as `feature/story-import-series`. Current intake only selects bundled/external stories. `ReaderRepository` stores canonical story documents; `ReaderProductionCoordinator`/`ProductionQueue` own paid work, recovery and immutable receipts. Existing `length:'auto'` performs recommendation/review without an extra count-confirmation wizard. Supplying an exact `Document.original` bypasses external lookup. `OriginalSource` survives revisions. Current quote validation verifies evidence exists but does not enforce coverage of every uploaded segment. `BookImageReferences` already copies a saved reference into each target story namespace. The Node HTTP envelope is 13 MiB; `FileMedia` accepts images/audio/JSON only. Existing source chapter expansion and corpus anomaly checks are unsuitable for arbitrary uploaded stories.

## Decisions

- Use one visible upload flow: **Upload → local extraction and automatic part plan → Create all parts → ordered series overview → ordinary comic reader/export**. Upload and planning make no AI calls. Part titles/count/source ranges are available before the creation action. Reuse existing art/detail/preferences; do not require classic discovery, manual splitting, per-part confirmations or balloon placement.
- Support modern Word `.docx` and selectable-text PDF, at most **10 MiB**, **500 PDF pages** and **2 million extracted characters**, with at most **200 planned parts**. Reject oversized/unsupported inputs before generation, without partial success or truncation. Report legacy `.doc`, encryption, empty/garbled content and scanned/image-only narrative pages clearly. Blank PDF pages are allowed; image-only pages are reported rather than silently skipped. OCR is out of scope.
- Extract plain text locally in a bounded worker (30-second deadline, bounded memory, at most two concurrent extractions), using pinned `mammoth@1.13.0` and direct `pdfjs-dist@6.4.299`. Validate signatures, DOCX structure and compressed/uncompressed limits, disable external document-file access and PDF evaluation, and never render converted HTML. Preserve canonical paragraph/page order, heading candidates and immutable source offsets. Mammoth raw-text extraction omits referenced foot/endnotes; therefore a bounded local semantic-HTML intermediate may be parsed to plain text to retain notes and headings. Expand notes at their references where possible and avoid duplicate endnote/backlink text. No converted HTML is stored, served or rendered. Reject unsupported content-bearing Word elements/warnings (including altChunk) rather than silently dropping embedded story text. Verify actual streamed ZIP expansion sizes, member CRC32 checksums and complete member sets before Mammoth; do not trust declared ZIP sizes alone. Worker resources must ship in source/CLI/desktop runtime; no system Office/Poppler dependency is required by the app. DOCX preflight bounds each ZIP member and aggregate expanded bytes before Mammoth runs; the isolated worker also bounds actual expansion/runtime rather than trusting claimed ZIP sizes alone. Stage the worker and its external Mammoth/PDF.js dependencies explicitly (a `new URL()` worker file is not a dependency import visible to the desktop entry metafile); retain required PDF.js local resource directories and package licences. Verify the worker through source/temporary Node module checks, without running desktop preparation or packaging.
- `lib/story-import-contract.ts` owns shared limits, settings, upload/source/part/series API types and schemas. `lib/story-import-text.ts` owns pure canonical text segmentation and deterministic part planning. Extraction returns full text and stable units `{id,start,end,page?,heading?}`. Unit ranges and part ranges concatenate to the full canonical source, without gaps, overlap or dropped last text. Prefer chapters, paragraphs and sentence ends; long paragraphs split safely at word/sentence boundaries. Source units target 700 characters with a hard 1,200-character bound at word/sentence boundaries; an indivisible longer token fails clearly rather than being split or truncated. A part contains at most 24 source units. Detail budgets are brief: target 16,000/hard 20,000 characters; balanced: target 10,000/hard 14,000; detailed: target 6,500/hard 10,000. Prefer the next chapter boundary once the current part reaches half its target; otherwise use paragraph/sentence-safe unit boundaries before the hard limit. No fixed four-part rule. A valid extraction remains saved and previewable when its first plan exceeds 200 parts; return an explicit planning error and keep settings available, so the reader can select Brief and replan without re-uploading or a silent detail downgrade. The server recomputes the authoritative plan from the saved immutable source at confirmation; client-supplied ranges, source text or membership can never replace it.
- Use owner-scoped support tables in ordinary migration `0022_story_import_series.sql`: immutable uploaded-source bytes/metadata/full canonical text/units, durable series settings and ordered reserved part IDs, and replay-safe series action receipts. SQLite backups naturally retain the original file and extraction checkpoint. Do not serve raw files through public/static/media paths, invent external source URLs or expose local filesystem paths. Update `db/schema.ts` and `db/library-format.json` through the normal upgrader; post-consolidation SQL must use the local app journal even when an obsolete D1 journal claims a future migration, and legacy imports require only actual pre-consolidation prerequisites; no schemaVersion bump is needed for additive support tables and safe paused child records.
- Uploaded sources are independent of bundled `LocalBooks`. Each generated part has `bookId:'other'`, uploaded title in `customBook`, `length:'auto'`, shared settings, and an exact pre-saved `Document.original` with `url:''`. Imported provenance records source ID/hash/range, series ID/title/part/count and distinct continuity context. Do not set `selection.source` or full-book `chapterContext`: neither may expand the part into other chapters. Bind imported creation fingerprints to source/hash/range/series/part. Distinguish immutable import provenance from active series membership: include the reserved part root ID and grant membership only when it matches the story family root (`revision.rootId || row.id`) and that root is reserved in the owner-scoped persisted series manifest. Independent copied stories retain provenance but detach from automatic series activation/navigation/reference selection; ordinary revisions retain membership. Never accept membership assertions from a client.
- Reserve stable part UUIDs in the series record. Create/activate only the next eligible child; newly persisted child stories start paused, then activate with an atomic guard that the series is still active and previous latest revisions are complete. A crash between creation and activation is recoverable without new IDs. Never resume an already manually paused/faulted part from a polling/synchronization pass. Parent controls persist normal child pause/stop, so older binaries cannot accidentally run queued parts.
- Integrate a local `StorySeries` synchronizer into the existing production coordinator cycle and run eligibility gate. It performs only idempotent database/source/reference preparation; **all text/image inference remains in existing story jobs**. No independent provider loop, planner queue, feature flag or production environment variable. API list/detail/source GETs are read-only; queue progress, not polling, activates authorized work. Command actions use expected versions and stable request IDs; unknown/stale/reused IDs fail clearly without duplicate children or paid requests. Store command fingerprints/receipts durably, applying the parent state/version and child pause/stop through an atomic SQLite command transition (the existing trigger/CAS pattern), so replaying an old pause after a later resume cannot reverse newer intent. Extend the existing coordinator queue candidate/claim guard with active parent, current child control and previous latest-part completion; apply that SQL guard again in the atomic paid-job claim rather than relying only on an earlier asynchronous `canRun` read. Recheck immediately before text/image provider dispatch after asynchronous source/reference preparation; if a pause has won, yield the job without a fault or a new paid attempt. Keep the existing `image-publish` drain alternative, so parent pause blocks new dispatch while already-dispatched paid operations and result publication retain their normal durable handling.
- A user-published genuine part revision or accepted explicit image-fault recovery atomically reopens a completed parent and increments its version, retaining all later completed parts. Image health checks and ordinary reads do not reopen or retry a completed series. A local next-part preparation failure exposes Retry preparation; a generation fault uses the ordinary child recovery action. Copies cannot reopen a series. An unactivated reserved child rejects direct per-part start/control/revision/paid preparation with guidance to use series controls, preventing a crash-boundary activation deadlock.
- Series status uses batched metadata/summary queries and an indexed owner/family lookup, not full saved prompt-history parsing for completed parts. Unfinished/faulted part state comes from the existing production snapshot. A measured 100-part poll performance regression drives this narrow change.
- Before each part, carry relevant prior summary/last-frame state and a cumulative character bible as non-adaptable continuity context. Merge prior retained identity context with the latest completed part bible, deduplicating stable named lines while retaining offstage identities. Use a generous 64,000-character guard and report overflow instead of silently dropping identities. New imported bibles use one `Name: identity and appearance` line per person. Snapshot the first completed part's anchor through `BookImageReferences`; derive its key from the unique imported series ID, never filename/title. Later parts use that reference automatically. Resolve current family revisions for source-order gates. Existing completed parts are not silently redrawn by later edits.
- Strengthen uploaded-source review using at most 24 deterministic English evidence units spanning the full current part. Add `unitId` to imported review coverage output and require every unit exactly once with a locatable quotation and corresponding frame(s) before accepting review. `needs-change` units must remain material review issues; incomplete or false coverage must fail before images. Reuse existing review/repair/structural coverage schemas and model call implementation. Known incomplete imported coverage cannot be waived by a presentation override: check the same saved full coverage before override and image dispatch. Ordinary style overrides remain available when source coverage is complete. Ordinary classic coverage remains compatible. Context/units are compiler-owned metadata, not instructions from document text.
- Shared production directions explicitly limit an imported comic to its exact part, cover all meaningful threads in that span, maintain established character identity/state and preserve open continuation for intermediate parts. Prior/future context cannot supply new present-part events. Source translation, when needed, precedes deterministic English evidence-unit construction, retaining original upload/ranges separately.
- Expose `POST reader/imports` (multipart file plus stable requestId), owner-scoped import metadata/source preview and a local plan endpoint, `POST/GET reader/series`, `GET reader/series/:id`, and versioned `POST reader/series/:id/control`. Series views include source metadata, automatic plan, shared settings, numeric part slots and current canonical session/status/ready counts. Source previews are explicitly paged; generation always uses the full saved span. All mutation origin checks and configured-provider checks remain production-owned.
- Add a visible home/New story upload entry, `StoryImportSetup`, `StorySeriesOverview` and `useStorySeries`. Show numeric ordered parts in the shelf independent of recency/urgency limits. Open each child using the current workflow/reader; previous/next part links are explicit navigation without new inference. Parent pause/resume and existing targeted child fault recovery remain distinct, understandable actions. Phone views use ordinary sheets and clear large controls.
- Root owns contracts, source/view projections, production prompts/coverage, manifest/docs and verification. Parser agent owns extraction/text planning, dependencies and worker packaging. Series agent owns support schema/storage/API/coordinator/reference integration and backend tests. UI agent owns client integration and browser tests. Shared APIs are frozen before parallel edits; avoid overlapping source ownership.
- Stop the current development service before schema/source implementation so a hot reload cannot migrate the personal library during unfinished work. Do not use that library for migration or generation checks. Test new schema/backups and generation only in isolated libraries. A later user-facing restart must use the normal verified upgrade gate and report any actual backup path. No desktop packaging/build is routine verification.

Dependency adjustment: the repository minimum-release-age gate rejected PDF.js 6.5.438. Use the compatible mature 6.4.299 release after verifying its Node24/API contract; do not bypass the release-age policy. Targeted architecture review retains the same bounded worker/API design. A later parser fidelity correction uses a non-rendered semantic HTML intermediate to retain Word foot/endnotes; the output remains plain text under the same worker bounds.

AR fixed: exact detail/source budgets, authoritative server-side plans, copy/membership authority, atomic command and paid-dispatch fences, and worker dependency/ZIP-bound staging were added. Independent rerun passed: no blocking architecture flaws.

## Rollback / Risk

Additive support tables do not replace stories/revisions. Normal upgrade initialization must verify a whole-library backup before migration; source bytes/extraction live in that backup. Do not restore a backup into a live directory. Old binaries cannot understand the series UI but must see unstarted children paused. Uploaded PDFs can be scanned/encrypted or have poor reading order: report unsupported extraction rather than claiming coverage. Local splitting cannot prove semantic perfection; gap-free source ranges plus independent complete unit review prevent known omissions from reaching illustration. A dense segment that cannot pass bounded production fails visibly with retained source rather than silently compressing away main events. Sequential generation preserves dependencies at the cost of throughput. Character/image continuity guides the existing models, not a guarantee of identical faces.
