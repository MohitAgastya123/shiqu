# 增量故事库服务级端到端

前置：隔离数据目录与受控模型适配器，实际应用REST/SQLite/媒体文件和生成队列；使用简短本地原文，记录 catalog 和 match 调用，禁止外部推理/原文网络调用。

1. 创建主题甲的新任务并提供真实查看者需求。提取先得到不匹配甲的故事A，再得到匹配甲的B。B必须带匹配理由与拟改编摘要；通用库保留A/B的中性摘要，提取输入没有甲，重复主题返回完整缓存资料。
2. 关闭并重启应用，为主题乙创建新任务。用库中A/B的摘要判断，A符合乙，不重新提取原文；再次查乙不重复匹配。
3. 受控模型对一条摘要返回review：第二次主题判断带该条真实原文，yes后返回；重复review或失败不当成no，库和cursor保留可重试。
4. 同时甲/乙查找共享一轮catalog；关闭一个查看者，另一个仍可得到结果；最后一个离开不派发下一块。选中B拒绝迟到候选/自动续找。
5. 选中B，把服务端候选拟改编摘要和理由随原文保存；现有画幅建议调用带摘要及原文，返回核对后的storySummary。完整确认前不生成分镜/图像。确认后短篇plan、长篇outline/batch按原文编排且不带storyBrief；审核有完整storyBrief，修订只据问题与原文。verifiedOriginal.text不被摘要替换。
6. 注入与原文冲突的拟摘要，准备调用返回按原文修正后的摘要；持久化并重启，再审核时只使用修正摘要，编排不传摘要。缺少核对摘要或返回非法内容时保存原文并失败，拒绝确认，不调用分镜；明确重试恢复。
7. 重选另一故事须清理旧原文及核对摘要；尝试从客户端制作命令伪造brief应被拒绝/忽略，不能覆盖服务端候选。升级前无能力标记且无brief的历史记录仍可按已有流程制作，新任务的旧式候选则须在准备时补齐摘要。
8. 主题任务各阶段保留editorialContext.mode=theme，短篇/outline/batch依原文编排；review参考主题和核对摘要审查完整性，repair按原文与具体问题改，不再次传摘要。保留开场、节奏、因果、静态画面和连续性。原典故事/忠于原文任务传mode=source且不带需扣题的theme；不额外造主题、动机或结局。
9. 新任务直接选择独立原典故事，跳过主题匹配但仍在准备时依据真实原文生成完整摘要；简介或“准备做什么”不能当核对完成。旧式主题推荐的新任务同样补齐。升级前已有分镜的历史记录不自动重做；无分镜且无摘要的旧式任务按新增兜底先生成摘要。
10. 三种provider的短篇、提纲/批次和审核/修订指令都保留第一页必要背景、人物关系和眼前处境要求，直接从原文提取必要背景做开场；不引入独立设局字段，不要求把全篇摘要或后续结局放入开场。
11. 创建升级前数据库，含stories.hook、任务plan/draft/outline/版本基线hook及媒体比较快照/缓存hook；部分同时已有summary。打开升级后SQLite列与这些对象均只有summary，已有摘要优先，否则旧文字无损迁移；状态、源文、图片、进度、版本关系与已付费回执不变。重启不重复更新，迁移失败可重试，导入也走同一路径。图片元数据改名导致的派生version/ID及依赖同步迁移，已成功绘制但尚未发布的回执仅发布、不重调模型，冲突失败回滚。新三provider、studio API、分镜显示/编辑与ZIP只读写summary。已核对brief的摘要覆盖模型误写引子，分镜前已生成；旧文本不因此标记已核对。
12. 对实际配置书库先生成一致性SQLite与待改JSON备份，再执行相同迁移；核对任务/故事/图片数量及内容指纹、原文/进度/版本状态不变，旧hook键/列消失，缓存中9篇摘要保留；不发模型请求。浏览器禁用时记录缺口，只认定服务与React渲染契约通过。
