# 审核记录ET

1. 使用正式队列和受控模型产生count调整→结构修订→count keep→full问题→局部修订→full通过；从GET历史读取顺序和结论、前后文本，刷新后仍一致。history GET前后比较会话/任务与调用次数不变。
2. 已有旧报告、有调用输入但无before字段：旧前文从对应请求恢复；无输入则明确未留存。结构增删有旧/新幅号，不把当前稿当历史。
3. 最新版本继承parent usage但无新审核：本版无记录，可看上一版真实报告并返回本版；其他用户或已删除版返回拒绝，错误可返回当前版。
4. 应用内浏览器打开当前真实故事的“审核记录”，读数量/全篇结果、修订对照与上一版，不点制作或重试生成；手机宽度检查长文本不溢出。开始制作按钮新文案保留原提交语义。

5. 在故事设置的制作流程标题行，“原文”紧邻“重新选择故事”；点击打开完整原文并关闭，阅读位置和制作状态不变；390px宽度操作组无横向溢出。

6. 制作流程末尾显示一个右对齐的“审核记录”链接，替换审核循环说明；与标题行“重新选择故事”右边缘一致，返回书架下方无重复入口，重绘预览说明不再显示。点击仍打开本版历史。
7. 验收unknown首次出现时，提示和修改入口位于全篇审片节点；第二次及以后出现时位于复核节点。已发生修订保持已完成，无修订不虚报已修订，绘图仍被阻止。实际旧版本只读验证入口打开验收编辑页，不提交或恢复生成。390px宽下提示仅出现一次，无横向溢出。
