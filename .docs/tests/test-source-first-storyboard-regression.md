# 分镜v1→测试v2：数量审核先行

1. 数量审核缺字段、方向不符、无补戏需求却要求调整、keep却有需求、非法数量/锚点/引用不能通过；需求派生的同幅issues合并且保留完整需求上下文；原全项审核保持。
2. 离线两阶段严格顺序：frames调整→结构编辑→frames复核keep→full全面审核；full再改结构回frames，full纯局部修订仍full；无任何绕过/媒体调用。
3. 每轮JSON检查点与请求哈希缓存：重启从已保存结果续接，不重复成功模型调用；非法输出/无变化/20轮上限停止，失败回执保留。纯函数范围/来源校验维持。
4. 三提供方共用数量schema、review推理档位；本地原文绑定无效时不调用；原全面审核主体逐字保持。
5. 真Codex九篇隔离：生产输入仅旧稿/原文/原制作要求，适中不变且length改auto。事后逐项核对关键戏，允许有据数量浮动；不靠模型passed或增幅算完成。原书架/正式队列/媒体均保持。

6. 第二篇失败样本的有界探针：新通用数量提示独立审已保存33幅，原文为唯一事实依据，无人工清单/参考36输入，须报告有据的未覆盖作用并通过引用/schema。新九篇仍须从旧稿独立跑，不把这一修复后的单篇当全篇完成。

7. 范围失衡探针：最终通用提示独立审自动扩到64的第三篇，主事件已在所选text终点完成，而章节上下文是新交锋；须检查可减/重分配，不把同场未离开当必补依据。同时保留主事件真缺结果时可补上下文，不把所选段落当不可变锁。

8. full遗漏身体处境的失败稿：足够幅数时同幅局部修，提示不含故事名/原文目标句/幅号，禁止新天气、伤害、病情。独立结语不计plot pages。
9. 系统稿继续迭代：父快照须稳定合法且有哈希/历史链，旧版本不覆写，清旧passed并重新两门，不继承正确性结论；完全同job+model才复用raw回执，九篇最终同规则验证，记录累计修订与失败。

10. 两门共用storyScopeDirection：不能因chosenStory偏窄删除同一行动目的尚在推进的换题/故事/回应阶段；也不能因同场强收主线完成后另起独立目的的交锋。对实际15与64反例都须真实验证，防止只堵一边。

11. characters-only全局修订：edits空但chars有实际变化才合法；正确pages不动、source/progress映射恒等、全局绘图输入变化使旧图片不可复用、历史保留旧新文字、预算只+1且不能绕20。无实际变化照停，其他元字段仍拒。三提供方可读旧edits输出。
12. full逐角色与取舍条件：次要角色独立触发/回应/立场不能只因不在核心冲突而跳过；保留对白的否定/比较/选择条件，元信息不冒充读者看到的表达。对实际50源稿做无人工答案探针，发现不等于成稿通过。

13. 已付费机审精确接续：完整job与requested/actual model相等才重放，整目录冻结收集；同job不同回执拒绝歧义，不根据有无issues选。首次入口未命中停止；冻结后源文件变化不改变已绑定内容。只有明确校验失败并与具体receipt对应才排除；SOURCE_QUOTE失败不封禁job，同job新合法回执可复用，TIMEOUT前有效count保留。分支保留父链累计20及全部失败，不宣称独立发现稳定。文件fixture与真实首入口cache/正常两门修订验证。
