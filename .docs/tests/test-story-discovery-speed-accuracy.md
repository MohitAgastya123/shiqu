# 故事发现速度、准确度与失败恢复：服务验收

依据：[REQ](../reqs/2026/11/01/req-story-discovery-speed-accuracy.md)、[AP](../plans/2026/11/01/plan-story-discovery-speed-accuracy.md)。

执行文件计划为`tests/story-discovery-speed-accuracy.e2e.mjs`，复用`tests/fixtures/production.mjs`、真实REST/队列/SQLite/FileMedia与可核对原文的假provider。每项使用临时数据目录、独立调用计数/可控promise；所有网络和Codex runner均由替身控制，不访问真实凭证/模型/用户任务。此文为规范，尚未执行。

1. **坏故事不挡后面的故事和未读原文。** 预置一个含4篇的库，第一篇拒答，其余包含符合项；发起按主题查找。合法项保存并返回，坏项不为no；移除本轮符合项并自动继续，可读后面的块。改为单篇超预算时该篇0调用，其余仍可找到。最后所有原文已读完且仍有unknown，接口及现有界面note说明判断不完整，不宣称全部检查无符合项。

2. **隔离预算跨自动续查与重启。** 假模型让多批的部分项非法，其余逐次给出可展示故事；通过真实`more, automatic:true`跨round继续，关闭查看者、重开并重启服务。整个cycle新增隔离≤8、每个失败批次新增≤缺失篇数、每篇至多单篇隔离一次。耗尽后仍能用正常未尝试项/新原文找符合项。已穷尽、无未展示yes后发起手动more才开始新cycle并允许重试旧unknown；重复requestId不产生新周期。预算预留写失败不派发，重启不补发不确定的已预留调用。

3. **服务故障不拆批。** 分别注入401/403、402/429、配置不符、5xx、网络断开、Codex启动/协议失败和未知提供商错误。当前查找停止派发、显示可重试错误、不新增unknown/no；其他已落盘判断保留。已在途合法结果完成后仍保存。推理超时与启动超时分别按可隔离/服务故障处理，取消不被当作故事失败。

4. **合法部分保留。** 一个四篇回执中分别制造一个短编号错误、缺失、重复或单项非法，其余合法yes/no走真实适配器解析路径；返回并保存合法部分，重复编号对应项不选有利答案，只隔离缺失部分。重启后合法判断不再调用。JSON外壳损坏可整批失败，但预算仍有界。三提供商的wire schema、reason/verdict顺序、短编号及完整原文用单元契约测试补足，同时捕获catalog和匹配实际序列化请求，确认稳定原文在excludeTitles/pending/contextText/theme等变化字段之前。

5. **单条坏缓存与跨章部分成功。** 预置有效故事/游标/pending及可直接返回的合法主题缓存，再混入一个字段或范围失效的故事/pending。经服务入口恢复并命中主题缓存，确认只去除坏项、无模型调用、已读完状态保持；修复写失败时不提取。随后注入一个独立合法新故事及不一致resolved/pending：新故事可匹配返回，旧pending和cursor不变、诊断保留；只靠无效续完证明才成立的项不入库。排除已展示故事后重试，合法回执明确用该已存故事结清旧pending，服务器核对全部旧证据后移除pending、推进本块，故事不重复提取/入库；未确认或只覆盖部分不得结清。pending减少/推进算进展，下一次没有任何故事、pending或位置进展才报可重试错误。

6. **并发早返与安全保存。** 已存至少12篇，三批分别用门闩阻塞；后批先返回yes。它立即可供API消费，不等前批，不新增第四批。释放其他两批后所有合法判断均保存，反序写不丢结果；热缓存yes不受槽位等待。两个读者/章节范围请求同一故事时只有一个在途判断；同服务所有正常/隔离调用在途总数≤3，共享隔离对每个依赖周期分别计费且同周期只计一次。

7. **选中/离开不破坏周期及其他读者。** 三批在途时选中一个已显示故事，释放迟到回执。选择和候选列表不被迟到结果改动；主题缓存仍保存完整合法回执，不再为该读者派发。一个查看者离开不停止另一个所需共享工作；最后一个离开后不新增调用，槽位直到实际调用完成才释放。重开保持候选/原文位置/cycle预算，既有制作准备门槛不退化、不调用图片。

8. **同篇跨范围和提取配置复用。** 同版同标题同原文范围先在全书获取yes/no，再换含同篇的不同章节范围、提取模型/档位/提示词重新发现同篇。主题判断调用数不增加；不同匹配provider/model/effort/语义契约或原文内容则不复用。仅短编号/字段次序变化仍复用。同名不同范围、不同版本、旧摘要回执不串用，保持章节主故事先于子故事的提取约束。另用冻结的旧匹配prompt/schema/键序列化和raw-title故事ID预置旧回执，传入fixture之外的新主题，证明按请求主题可重算旧键、映射到新身份并复用；不能硬编码某个已知主题键通过。

9. **扩批不跳原文。** 冷库首篇只请求1；不符合后对同一块按有限上限提取，9篇fixture总提取≤2、预期9篇各一次。最大容量回执即使写blockComplete也不跳块；截断或不完整回执不推进。既有符合项直接返回不启动扩批。世说1129条预期完整定位（1072条有效故事各一次、57条原有防线拒绝显式核算）、≤60调用和五书分块阈值由专项离线集成测试执行，不能以服务小fixture替代。

10. **新分块迁移可重启。** 用冻结的旧v3键/manifest建立全书及章节旧库，分别包含已读完、前沿正好落新块边界、前沿落新块中间三种情况；升级并重启。已存故事/pending保留，已读完库0提取；只允许包含前沿的新块重读，后续不再向前回退，旧文件逐字节不变。迁移写失败后不提取，恢复重试成功；晚到旧读不覆盖新状态。缺失或不可信旧manifest不冒充已读覆盖。

11. **重叠与推进优先级。** 用娇杏/黛玉已有定位及新编高重叠不同完整事件回执验证入库，不按标题白名单；同范围、同名重叠、无增量交叉仍拒绝。只有重复、未满额且明确读完时推进；混入非法范围、跨章错误或满容量则保持位置。不让疑似重叠诊断变成额外模型调用。

12. **测量无敏感信息、离线评测不漏失败。** 请求内植入独特原文/主题/凭证/错误正文标记，捕获三适配器成功、部分非法、故障、unknown、取消后完成的测量事件：实际调用各一次、共享不重复、缺失usage为null，标记不进入日志；查找区分首篇入库与首个符合项，包含早返后的在途费用。默认eval在拒绝一切网络/runner的环境下运行，手算TP/FP/FN/unknown与边界清单吻合，缺失/不可比回执不冒充已完成评测，输出标注草稿状态。边界小样本包括一对一精确命中、重复不能加分、无交集漏提、非包含预期的合并、覆盖并集拆分、缺首/尾、合法背景共享及嵌套；分母按预期故事数、诊断可重叠且不求和，不能把缺首/尾描述成已证明缺因果。

13. **现有界面检查。** desktop preview是shell，不能直接渲染reader。以测试专用`tests/fixtures/story-discovery-preview.mjs`在临时书库绑定productionFixture的`app.handle`到loopback HTTP，程序化启动代理至它的reader Vite（假provider、拒绝外部请求、不加载.env、不运行会启动真实后端的`pnpm dev`），再以相同临时`SHIQU_DATA_DIR`和`VITE_DESKTOP_READER_URL`运行`pnpm desktop:preview`。复用相关in-app browser标签，从桌面阅读入口进入隔离reader，观察多章压缩进度、unknown不完整提示、逐篇显示与选择停止。临时harness仅测试使用，不增加产品设置；不得点击真实任务重试。IAB不可用则保留未验证状态并记录原因；REST/受控服务测试不冒充浏览器视觉证据。

本故事不授权真实模型评测、Docker/桌面打包或修改用户实际库。首次真实评测另报调用数并获得授权；此文件不记录任何已通过结论。
