# Impact-based routing verification

1. Registry completeness: every JS regression/E2E and native test module has valid explicit metadata. Add an unregistered file or invalid group/platform: validation fails before executing a partial suite.
2. Adapter split: compare original/moved declarations and run request/configuration contracts plus corresponding controlled production flows. No assertion is deleted; every provider still has a fast contract entry.
3. PR decision table: docs, client CSS, reader requests, settings, provider adapter, discovery, count/review, queue, image/reference/export, database migration, native Rust, shared model, Node/dependency and unknown changes. Verify base inclusion, affected-domain unions, six-service selection for core changes, native requirements, and no unrelated costly suites.
4. Renames/failure/test changes: old and new paths both matter; empty/invalid Git comparison selects full. Changed test and shared fixture select owners/consumers. Unsupported platforms are explicit rather than silently treated as passing native coverage.
5. Execution: fake registered suites prove exact-once selection, fast/full environment isolation, nonzero failure propagation and evidence identity. Existing full/extended/release/npm selection contracts remain valid.
6. CI events: docs/code/failed-scope PR; native PR passing/failing; main push; release tag; manual dispatch. Shared checks must reflect selected JS/native failures. Main/tag qualify full JS; artifact jobs remain tag/manual and wait for qualification.
7. Timing: immutable pre-change baseline versus proposed selections using the same source/dependencies/Node. Report wall time and file counts for representative PRs; distinguish setup, full/native added coverage and hosted estimates.
8. Source identity: migration, book, asset, lockfile, Node and unknown untracked edits change the receipt fingerprint; ignored runtime data does not. Release and full lifecycle wrappers retain distinct creation-case evidence.
9. Local agent mode: staged, unstaged, untracked and renamed paths are included; preview and explicit task-path overrides share the CI planner.
10. Isolation: no live models/user libraries, no desktop preparation/packaging, no modifications to concurrent desktop files or their specifications.
