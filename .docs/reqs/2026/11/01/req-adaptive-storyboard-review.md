# 按叙事需要编排与审核画幅

当前系统会核对原文，却没有保存可检查的“原文言行—叙事任务—分镜”对照。故事提到了某件事，就容易被当作已经表现了这场戏；幅数又先于提纲锁定，审核只能挤改现有画幅，结构问题交回用户。用户实际上被要求替编剧决定篇幅。

本次将九篇《红楼梦》重编中使用的审核方法写成系统规则：读者选择叙事详略，模型决定幅数，审核可按有据的缺失、拥挤或重复增删画幅，完整复核通过后才绘图。多幅不等于更好，详略不绑定固定数量。

- [x] 记录完整的审核方法、实际问题类型、原文依据和判断边界；明确文字复核不能证明成图合格，也不能把九篇个案当普遍质量基准。
- [x] 新建与修订 UI 只提供简短、适中、详细；不提供幅数输入/滑块。推荐幅数是估计，最终幅数来自提纲与审片。新 UI 使用已有 `length:'auto'`，旧数值数据和旧 API 保持兼容，不重写历史成品。
- [x] 审核独立从原文识别关键言行、回应、停顿、因果及自然结局，并保存原文短引、任务、对应幅号和判断理由。缺失/拥挤/重复须有具体修法，不能只输出“加强细节”。
- [x] 自动幅数故事的结构问题进入受限结构修订，可插入、删除、替换局部画幅；校验范围、顺序、不重叠及总幅数1–80。无实际变化、循环超限或非法输出阻止绘图，不假装通过。
- [x] 结构修订保存后重新全篇审核；编号、完整分镜、进度和已存图片同步，重启/重试沿用检查点，不因新增幅数提前画图或重做已保存调用。
- [x] 画风、人物、全局要求与首幅参考稳定时，移动位置的相同画面可复用；每张旧图最多使用一次，重复提示词不猜配。首幅变化仍使依赖图片失效，纯配文变化保留图。原版及独立媒体保持。
- [x] 定向测试覆盖增幅、减幅、非法/无变化编辑、审核闭环、旧图移动与图片失效、历史记录与旧数值 API；完整本地检查通过，并在原内置浏览器核验新 UI。

范围：分镜编排、审核、修订和制作 UI。不改原典、图片模型、推理档位、付费并发、数据库表或发布版本；不自动重编现有书库，不实际生图，不打包 Docker 或桌面应用。
