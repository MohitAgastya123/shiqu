# 增量故事库与主题匹配

现在的扫描由主题驱动，换主题要重新理解原文，找到的故事也无法跨主题复用。将稳定的原文理解和变化的推荐判断拆开：逐篇识别完整故事并持久化，再根据主题筛选；首次阅读逐步积累，以后优先复用。

- [x] 本地原文提取不接收主题或制作偏好，只产出标题、短简介和可核对原文范围，不生成summary或storyBrief；未完事件只记录名称、ID和范围，后续按真实原文续读。支持完整主故事及严格包含的小故事，拒绝重复范围和交叉碎片。
- [x] 不预扫描全书；先匹配已有库，必要时从共享阅读位置继续识别，找到符合主题的一篇即返回。保留选中/离开停止、跨章未完事件与阅读位置恢复。
- [x] 主题匹配直接读取每篇故事已核对的原文，批量返回id、yes/no和一句有原文依据的理由；不读取或生成摘要，不再有review/原文二次核对阶段。调用失败、非法回执、原文缺失或超预算均是可重试错误，不写作no。
- [x] 通用故事库跨主题、任务和重启复用；主题正反判断单独缓存，按原文身份、匹配契约、有效匹配模型和档位隔离。升级复用旧通用库的可信定位与阅读进度，不重扫已识别原文；旧摘要匹配回执不当作新原文判断，不删除旧文件。
- [x] 旧主题缓存不冒充通用库的完整覆盖，保留旧文件及已保存任务候选；新目录从可证明的位置起步。并发主题共享提取，主题判断彼此独立；取消一个读者不终止其他读者需要的共享工作。
- [x] Codex、Gemini、OpenAI均支持无摘要提取及原文批量二元匹配。Codex/OpenAI主题匹配单独采用gpt-6-luna/low，分镜/摘要/审核保留原模型；Gemini使用自己的文本模型和low，不跨提供商或引入凭证/自动降级。匹配模型身份可观察且单独影响主题缓存，不使中性库失效。
- [x] 候选阶段没有生成摘要，仅返回匹配理由和原文定位。用户选中后，主题/原典模式均在首次分镜前按真实原文生成或核对summary并保存，复用现有准备/画幅建议调用；不以简介或匹配理由充当摘要。缺结果阻止确认/编排，重选、重启和重试保持来源绑定；已有完成分镜不重做。
- [x] 短篇分镜、长篇提纲及分批细化依据已核原文编排，模型输入不带独立storyBrief、匹配理由或嵌套在outline/draft/plan中的summary；标题/结语生成及定向修订同样不以摘要作脚本。保留原文、必要提纲节点、前批分镜及制作要求，继续开场、节奏、因果、静态画面和连续性规则。审核先依据原文独立检查，再参考主题、匹配理由及摘要核对范围、关键阶段与结局遗漏；摘要错误时服从原文，不要求分镜迁就摘要。
- [x] 不另设“设局”资料项。第一页直接从原文提取看懂开局所需的背景、人物关系和眼前处境；不把摘要当开场，不提前泄露后续结局。摘要保留生成、缓存和归档用途，审核时作为完整性参考。
- [x] 类型检查、lint、完整单元/集成测试及修正后的受控端到端用例通过，记录真实推理/浏览器证据的边界。
- [x] 故事、分镜/提纲、编辑/版本快照、接口、展示及ZIP导出统一使用 `summary`，运行时不再读写 `hook`，不保留别名。新摘要允许完整叙事长度；初始空草稿可为空。已核对的制作摘要进入分镜元数据，不在分镜阶段另写引子。

不做：全书离线预处理、向量数据库、嵌入检索、主题同义词归并、自动后台扫完整书、SSE、新增界面流程或桌面/Docker打包。允许将现有引子展示/编辑替换为摘要。冷启动多一次轻量主题判断是代价，跨主题复用是收益；不承诺没有真实模型证据的延迟或准确率数字。
