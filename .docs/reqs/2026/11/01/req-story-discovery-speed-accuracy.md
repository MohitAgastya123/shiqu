# 故事提取与主题匹配的速度和准确度

## 问题

代码审查发现，提取与主题匹配的设计可用，但有三类问题：

- 个别失败会让读者卡住，或丢掉已付费的结果。
- 同一块原文被反复阅读，部分书的阅读块过小，主题判断重复付费。
- 提取和匹配路径没有耗时与用量记录，也没有带标注的评测集，无法判断真实速度和准确度。

已用受控假模型复现的行为：

- 一篇总是失败的故事，让同一主题的三次查找都停在同一批。
- 一篇失效的已存故事，让已读完的两篇故事库被清空。
- 跨章记录不一致时，同一回执中有效的故事被丢弃。
- 一块含9篇故事时需要4次提取调用（1、4、4、4篇），每次重发整块原文。
- 返回id错一个字符，整批判断作废。

本地测得的阅读块数：

| 书 | 现有块数 | 备注 |
|---|---|---|
| 战国策 | 251（中位529 token） | 去掉两章上限后为17块 |
| 三国演义（Gemini） | 239 | Codex下为74块 |

## 目标

失败只影响出问题的那一篇，已付费结果不丢失；同样的内容少读、少判、不重复付费；速度和准确度可以被测量。减少调用次数不等于降低等待时间，也不等于提高准确度；本轮交付可靠性修复、调度优化和测量能力，不宣称尚未实测的收益。

## 查找与失败的边界

一次查找周期从创建选题或用户手动继续/重试开始，包含其后的自动连续查找请求；HTTP请求、候选显示、关闭后重开、进程重启均不重置该周期的隔离预算。只有新的显式手动继续/重试才开始新周期。无选题任务的独立建议接口以一次请求为一个周期，不自动续查。共享调用只执行一次，每个依赖它的周期均计入自己的预算，不能靠加入另一个读者绕过上限。

“未判断”只指某篇原文无法得到合法判断，不代表no。批量拒答、非法回执或推理超时可进行有界隔离；账户/额度/速率/配置、明确网络故障、服务端故障及原因不明的提供商错误按服务故障停止新调用，不推断为某篇的问题。已在进行中的调用允许完成并保存合法结果。

## 验收标准

### 失败隔离与结果保留

- [ ] 一篇故事的判断持续失败（拒答、非法输出、超预算、超时）时，同一主题仍能继续判断后面的故事并返回符合项。
- [ ] 未判断故事不阻止判断后面的故事或继续读取未读原文。只有当前范围原文已读完、其余可用故事都已判断且没有未展示符合项时，新的手动查找周期才重试它们。一次失败批量之后，每篇最多再单篇隔离一次，同周期后续请求不再重试该篇；超预算的故事不发起调用，仅在原文、预算或匹配配置改变后重新检查可调用性。
- [ ] 服务故障立即停止派发并报可重试错误，不拆批，不将受影响故事记为未判断；其他批次已保存的判断保留。
- [ ] 一批失败后新增调用不超过该批未获合法判断的篇数；每个查找周期的隔离调用合计最多8次，发起前预留额度。耗尽时未完成判断保持未知，不写no，不继续隔离；仍可正常处理其他未尝试故事及未读原文，最终说明判断不完整。网络故障后不再派发正常或隔离调用。
- [ ] 存在未判断故事且原文已读完时，提示须说明有未能判断的故事，不得宣称已检查完且没有符合主题的故事。
- [ ] 已存故事库中某篇故事或未完事件失效时，只移除该条。其余故事、阅读位置和其他未完事件保留，不额外调用模型。
- [ ] 跨章记录不一致时，同一回执中可独立通过原文与完整性校验的故事仍保存，原未完事件保持不变，本块不算读完，并保留内部诊断。依赖无效跨章证明才成立的故事不入库。有新故事入库时继续匹配，不向读者报错；没有任何进展时才报可重试错误。后续合法回执可明确确认由已存完整故事收束旧事件，经服务器重新核对对应关系和全部旧证据覆盖后结清pending，不要求重复提取或重复入库；仅范围包含不能自动结清。

### 减少重复阅读

- [ ] 冷库的第一次提取仍只要一篇，不为凑批等待；已有符合项直接返回，不启动扩批提取。分别测量首篇入库耗时与首个符合项返回耗时，不以“一篇请求”证明首篇速度不退化。
- [ ] 之后对同一块的提取一次尽量识别完本块，每次篇数不再固定为4；模型输出schema、运行时校验上限与本次请求一致。每次篇数同时受有限的故事数及输出容量约束；截断或不完整回执不推进阅读位置，不无限增大输出或重试。
- [ ] 固定原典版本、完整预期定位清单及假模型下，含9篇故事的块不超过2次提取调用；按需查找持续到读完世说新语（1129篇）不超过60次提取调用，且1129条原文全部覆盖：1072条符合现有原文防线的预期故事恰好入库一次，57条被原有防线拒绝并按定位/原因显式核算（56条短于20字符、1条含未审核异常），不得静默遗漏或放宽防线。回执达到容量上限时继续本块，不跳过未识别内容。这是调度回归指标，不作为真实模型完整率或速度证据。
- [ ] 主题匹配仍为每批最多4篇，找到符合项即可返回。
- [ ] 阅读块不再按固定章节数限制，过小的相邻章节合并，单块仍不超过现有输入预算。以同版原文、Codex本地容量估算口径比较：战国策不超过60块、中位不低于2000 token；世说新语、庄子和搜神记的块数不增加；三国演义的块数与旧计划相比变化不超过5%。原文单元有序、无遗漏、不重复。
- [ ] Gemini不再把字节数当作token数；本地估算与提供商实际用量分开标记，同版三国演义的Gemini块数不超过Codex块数的1.5倍。预算检查不调用远端计数接口，不以放大输入预算达到块数目标。

### 减少重复判断与失败重来

- [ ] 主题判断按原典版本、故事身份（标题、原文范围及对应原文内容）、主题及匹配契约复用。同一篇在全书和不同章节范围之间、提取模型或提示词变化之后都不重复判断。匹配提供商、模型、档位或语义契约变化仍使判断失效；仅批内短编号或序列化次序改变不单独失效，旧摘要判断不复用。
- [ ] 主题匹配的回执中，单个id抄错、遗漏或重复时，其余合法判断照常保存，只重新判断缺失的故事。模型不再需要逐字抄写64位id。
- [ ] 主题判断可受限并发，同一服务进程合计同时不超过3批（包含正常与隔离调用），同一故事/主题/匹配身份不重复在途判断。任意完成批次有符合项即可返回，不等待较早批次；同一回执内仍按原文顺序展示，不承诺跨批全局原文顺序。找到符合项后，该查找不再发起新批次，已进行中最多另两批照常保存，接受这部分可能额外付费的代价；其他读者仍需要的共享工作继续。单篇失败不影响其他批次；服务故障停止后续派发。并发写入不丢失判断，取消语义不变。
- [ ] 提取和匹配请求把稳定的长原文放在变化字段之前（如已排除标题、未完事件、主题），便于提供商复用提示缓存。不承诺缓存收益。

### 准确度

- [ ] 主题匹配回执先给出原文依据，再给出yes或no。
- [ ] 原文单元交集超过较短一方80%且互不包含时，只记为疑似重复诊断，不凭比例自动拒绝。拒绝同范围改名、同名重叠，以及无新增原文、无已核对续完关系且不被既有主故事包含的交叉拼接；有新增原文或已核对续完关系的不同完整事件可共享背景，主故事可严格包含独立小故事。娇杏、黛玉及新的高重叠不同事件均有回归，不按故事名设白名单。不新增二次语义审核调用。
- [ ] 仅因与已存故事重复而拒绝时，模型明确确认本块读完且未满容量，可推进阅读；原文无效、跨章记录不一致或已满容量仍不推进，不能用blockComplete掩盖校验失败。

### 测量

- [ ] 每次实际提取和匹配调用（含失败、隔离及取消后完成的调用）只记录一次阶段、提供商、模型、档位、耗时、受限结果状态、请求/合法返回篇数，以及提供商返回的输入输出token。用量缺失记为未知，不填0，不用本地估算冒充。不记录原文、主题、凭证、原始错误或提供商响应正文。
- [ ] 查找测量分别输出冷库首篇入库耗时、首个符合项返回耗时、调用数、隔离调用数及实际token用量；缓存命中、无符合项、失败及取消单列。受控时序可验证不等待无关批次；真实延迟只在另行授权的同输入比较中评估，不设未经测量的提速承诺。
- [ ] 提供标注草稿：合计30–50组“故事+主题”，覆盖至少3本书，包含正例、负例、容易混淆的主题及共享背景事件；至少3章的完整故事定位清单。标明原典版本、样本来源、标注状态及录制回执的模型/档位/契约身份；用户确认前不称为准确度基线。
- [ ] 评测工具按全部固定样本输出主题判断精确率、端到端召回率及判断覆盖率。未判断/拒答/非法回执不伪装为no；正例未判断计入召回损失，分母为0时输出不适用。另列已判断样本的召回率和失败数量，避免只报告成功样本。
- [ ] 边界评测以同章完整预期定位清单作一对一比较，精确范围命中率为范围完全相同的配对数/预期故事数；另报无原文交集的漏提、未精确配对/重复提取，以及按范围关系确定的合并、拆分、缺首或缺尾诊断。这些定位诊断不冒充对因果完整性的语义判断。默认离线回放，不产生费用；只有输入、标注版本和语义契约可比的已录制模型/档位结果才并列比较，缺失结果显示不可比较，不借用另一模型的回执。回放验证工具与回归，不证明当前模型质量。

### 迁移与回归

- [ ] 升级后已有故事、未完事件和阅读位置继续有效。除新块跨越旧阅读前沿时允许重读包含该前沿的一个新块外，已完整读过的旧块不重新提取；重读复用已有故事，之后不能再向前回退。已读完的库保持读完。迁移可重启重试，旧文件不删除；未知或无法证明的旧覆盖不冒充已读覆盖。
- [ ] 上述复现场景均有回归测试；类型检查、lint、完整单元和集成测试通过。

## 约束

- 保持不变：提取与主题无关、原文范围核对、异常字防线、发现阶段不生成摘要、匹配读取完整原文、取消和离开时保留已完成回执。
- 提供商层不增加自动重试或模型降级。隔离失败的拆分属于发现流程，遵守上述调用上限。
- 真实模型调用须另获授权；测试和复现只用假模型或已录制回执。
- 不打包Docker或桌面应用，不增加数据库迁移，不新增界面流程或设置项。
- 不承诺尚未实测的提速或准确率数字。

## 取代的既有要求

本需求取代 [增量故事库需求](req-incremental-story-library.md) 中的以下内容：

- “无匹配继续识别时一次最多4篇”：匹配仍每批4篇，提取不再固定4篇。
- “合法整批回执”后才保存：改为逐篇保存合法判断。
- “原文缺失或超预算均是可重试错误”：单篇超预算改为未判断并继续后面的故事。不写作no的要求保持。

## 不做

- 审查中列为不紧急的项：大型库缓存查找的平方增长（目前最大库只有23篇）、Codex每次调用新起进程。匹配保留现有超时和输出容量；本轮须覆盖新回执最大4篇的容量回归，不扩大为模型容量调优。
- 按结构直接切分世说新语等书的故事，不调用模型。
- 全书离线预处理、后台扫完整书、向量检索、主题同义词归并、评分排序、恢复独立的二次审核阶段。
- 合并全书与章节范围的故事库（只共享主题判断）。
- 整份缓存文件损坏时的处理方式不变。

## 待确认问题

以下问题不阻塞规划，暂按默认处理：

1. **评测标注由谁确认？** 默认由agent起草并标为草稿，用户确认前不作为准确度基线，也不据此调整模型或档位。
2. **是否授权真实评测？** 默认本轮只交付工具和录制回放；首次真实运行前报告预计调用次数，待授权后再执行。
