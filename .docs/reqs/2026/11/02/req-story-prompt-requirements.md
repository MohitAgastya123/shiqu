# 故事自己的制作与验收要求

用户需要看到生成行为背后的规则，并分别决定怎样制作、怎样才算合格。当前制作要求只是偏好，系统规则隐形，审核标准不能逐篇设置。

## 验收标准
- [ ] 制作确认、暂停编辑、阅读后的制作流程有同级“制作要求”和“验收要求”入口；不新增第三个提示词入口。
- [ ] 每篇故事分别保存制作要求和验收要求，支持草稿、重开、选择故事与新版继承；旧记录可读，缺省验收要求为空。
- [ ] 两入口内可展开、复制对应阶段的完整应用提示词（系统指令、文本输入、输出契约）；明确区分当前规则预览与实际使用记录，记录跟随故事版本，旧记录不伪造历史。图片参考显示引用，不复制图片二进制。
- [ ] 验收要求进入编排、审核及修订；审核逐条返回通过/未通过/无法判断、幅号及依据。未通过或无法判断不视为通过，进入现有修订/阻断路径；冲突须明确说明并遵守原文事实、画风、数量及输出约束。
- [ ] 仅修改验收要求创建新版并重新审核，保留原分镜与可复用图片；审核引发实际画面变化时才失效相关图片。原版本保持不变。
- [ ] 界面提供验收结果和无记录状态；已有自动修订、选题确认、图片复用及历史提示词指纹不退化。

## 约束与非目标
使用 pnpm 与指定 Node；不构建 Docker 或桌面安装包。不提供任意覆盖系统底线的编辑器、不增加模型调用来生成验收标准、不把文字分镜审核冒充实际图片视觉验收。不保证模型语义判断质量，验证实际请求契约与受控流程。
