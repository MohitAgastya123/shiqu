# 书库备份恢复、故障诊断与发布回归

## 问题与决策

作品与已付费结果依赖本地数据库和媒体的一致保存。目前升级备份依赖手工复制，桌面错误缺少可携带的诊断，浏览器生命周期回归没有进入发布检查。本轮把这些能力接入真实 CLI、开库和服务生命周期；保持本地优先，不增加云服务。

## 验收

- [ ] R1：CLI 可在停服后创建完整书库备份，数据库使用一致快照，媒体/缓存原字节保存，清单含大小与 SHA-256；验证能拒绝缺文件、篡改、额外文件、符号链接及非法相对路径。
- [ ] R2：恢复先验证备份，只发布到不存在的新目录，失败不留下可误用的半成品，不覆盖任何已有书库；恢复后检查数据库、故事/版本/任务、媒体及阅读进度。恢复操作及显式只读验证不产生模型调用；之后正常启动保留既有控制和后台制作语义。
- [ ] R3：已有书库存在待执行迁移时，任何迁移写入之前自动创建并验证一次升级前备份。备份失败则不开启升级；新库与无迁移重开不备份。备份不删除旧备份，能恢复到对应旧结构。
- [ ] R4：维护备份必须拒绝使用中的书库；开发、CLI 和桌面使用同一服务锁。维护操作不配置提供方、不启动服务、不调用模型、不读取真实凭据。
- [ ] R5：CLI/桌面/开发服务保留容量有界、私有权限的安全诊断事件，包括启动/停止、已知任务错误、请求错误。只允许事件名、时间、任务ID、受限错误码和计数，不记录密钥、正文、提示词、原始异常或提供方响应。
- [ ] R6：CLI 可导出脱敏诊断 JSON，包含应用/运行时版本、数据库检查与任务计数及近期安全事件；不导出书名、原文、提示词、路径、凭据和模型原始回执。损坏/丢失的库仍能给出受限诊断结果。
- [ ] R7：本地发布检查在同一待发布提交中执行现有 E2E，失败阻止发布；不把完整回归重复放回平台构建，不运行打包或真实AI作为普通验证。
- [ ] R8：文档给出备份、验证、恢复、诊断、升级回退步骤和凭据边界；单元/集成、类型、lint、匹配 E2E 验证通过，所有验证仅使用隔离数据。

## 边界

备份是私有目录快照，不是公开作品 ZIP；不包含书库之外的 desktop.sqlite 凭据，不自动恢复提供方设置。恢复不自动切换用户默认书库、不自动升级备份、不发起制作。已有控制/历史/付费回执原样保存，正常启动沿用既有状态机。CLI 是本轮操作入口，不增加桌面页面、云备份、定时备份、加密存储、自动清理策略、安装包或版本发布。自动备份空间不足时停止升级，保留用户原库。

无待确认的产品决策。
